# AP-17 packages A and D — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a foreign AP-17 trip pay on the manager's approval date alone, and rewrite the three manager notification emails so they are written for the requester who receives them.

**Architecture:** Both packages are changes to existing pure modules plus their call sites. `payout-rule.ts` keeps its bands and changes only which date feeds them, branching by trip kind. `email-templates.ts` gains an optional actor parameter and new rows on three of its six cases. No schema change, no migration, no new endpoint.

**Tech Stack:** TypeScript, `node:test` + `node:assert/strict` via `tsx`, React 19 (copy only).

**Spec:** two, both required reading —
`docs/superpowers/specs/2026-09-21-ap17-d-foreign-payout-date.md` (Task 1) and
`docs/superpowers/specs/2026-09-21-ap17-a-mail-copy-and-title.md` (Tasks 2-4).

## Global Constraints

- **Package A must land before package C**, a later package that makes the ID-card field conditional. Both edit `IdCardUpload.tsx`. Nothing in this plan depends on C.
- `npm run typecheck` (= `tsc --noEmit`) clean before every commit.
- Full suite must not drop. Record its count on the branch before Task 1 and compare after each task.
- Tests are `node:test` + `node:assert/strict`, discovered by a walker over `src/` for `*.test.ts`. Import **values** relatively (`./payout-rule`), never `@/` — `tsx` does not resolve the alias in a bare test run. **`import type` is exempt and may use `@/`**, because it erases at compile time and is never resolved at runtime; `src/lib/acc/calc.test.ts:4` already does exactly this with a type from `@/features/`.
- **ES5 target:** `Array.from()` only, never a spread over a Set or Map.
- In-page and email copy is **Thai**. Every string in this plan is final copy — use it verbatim, do not paraphrase.
- `email-templates.ts` escapes all interpolated values through `row()` / `shell()`. Any new row must go through `row()`; never concatenate a value into HTML by hand.
- No database, no migration, no dev server in any task.

- [ ] **Step 3: Write the implementation**

```typescript
export function payoutDateFor(
  kind: PayoutTripKind,
  approvalYmd: string | null | undefined,
  travelReturnYmd: string | null | undefined,
): string | null {
  // **The two kinds disagree about D, not only about how D maps to a payout
  // day, and that asymmetry is deliberate** (user, 2026-09-21).
  //
  // foreign  D = the manager's approval date. The return date is not read.
  // domestic D = the later of approval and return, unchanged.
  //
  // This reads exactly like a bug — a maintainer who notices `foreign`
  // ignoring `travelReturnYmd` will "fix" it to match `domestic`. It is not.
  // See the header for what was given up.
  const determining =
    kind === "foreign" ? approvalYmd : payoutDeterminingDate(approvalYmd, travelReturnYmd);
  return payoutDateForDetermining(kind, determining);
}
```
